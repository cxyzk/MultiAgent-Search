# 固定窗口与滑动窗口限流

固定窗口（Fixed Window）和滑动窗口（Sliding Window）是两种基于"计数"的限流方式，比令牌桶更容易实现，但在精度和内存上有不同取舍。

## 固定窗口

按时间切成固定长度的窗口（如 1 秒），每个窗口独立计数：

```python
import time

def allow_fixed_window(redis, key: str, limit: int = 100, window: int = 1) -> bool:
    bucket = int(time.time()) // window       # 当前属于第几个窗口
    k = f"rate:{key}:{bucket}"
    count = redis.incr(k)
    if count == 1:
        redis.expire(k, window)
    return count <= limit
```

### 致命问题：窗口边界突刺

假设限制 **100 请求/秒**：

```
时间轴:  |---- 窗口1 ----|---- 窗口2 ----|
请求:    ... 90 个 ... 10 个 | 90 个 ...
                 ↑ 边界前后 200ms 内实际通过了 180 个
```

**窗口边界的 200ms 内可以涌入接近 2 倍的请求**——因为两个窗口各自独立计数。

这是固定窗口在高并发场景下最被诟病的地方。

## 滑动窗口

滑动窗口把"1 秒"再切成更细的格子（如 10 个 100ms 的格子），统计**最近 N 个格子**的总数：

```
| 100ms | 100ms | 100ms | ... |
  ↑ 只统计"当前时间往前 1 秒"覆盖的格子
```

### 实现（Redis ZSET）

```python
import time

def allow_sliding_window(redis, key: str, limit: int = 100, window: int = 1) -> bool:
    now = time.time()
    k = f"rate:{key}"
    pipe = redis.pipeline()
    pipe.zremrangebyscore(k, 0, now - window)          # 清掉窗口外的记录
    pipe.zadd(k, {f"{now}-{id(now)}": now})            # 记录本次请求
    pipe.zcard(k)                                       # 统计窗口内总数
    pipe.expire(k, window)
    _, _, count, _ = pipe.execute()
    return count <= limit
```

**代价**：每个请求都要写一条 ZSET 记录，内存和 Redis 写入压力随 QPS 线性增长。1000 QPS 下 1 秒窗口就是 1000 条记录。

## 三种方案对比

| 方案 | 精度 | 内存 | 实现复杂度 | 适用场景 |
|---|---|---|---|---|
| 固定窗口 | 差（边界突刺 2x） | 极低（1 个计数器） | 低 | 粗粒度保护、日志限速 |
| 滑动窗口（格子） | 中（格子越细越准） | 中（格子数 × key） | 中 | 通用 API 限流 |
| 滑动日志（ZSET） | 高（精确） | 高（每请求一条） | 中 | 低 QPS 精确限流 |
| 令牌桶 | 高（平均速率精确） | 低 | 低 | 需要突发能力 |

## 工程建议

1. **优先令牌桶**——精度够、内存低、支持突发，是大多数场景的最优解
2. **必须用固定窗口时**，把窗口切小（如 100ms 一个窗口、限制 10 个），边界突刺从 2x 降到约 1.1x
3. **滑动日志只用于低 QPS**（如登录失败次数限制，每分钟 10 次），高 QPS 会拖垮 Redis

## 常见坑

1. **`incr` 和 `expire` 非原子**：进程在 incr 后崩溃，key 永不过期，计数只增不减 → 用 Lua 或 `SET NX EX` 兜底
2. **时间戳用应用服务器时间**：多机部署时钟不一致会导致窗口错乱 → 统一用 Redis 的 `TIME` 命令
3. **key 设计漏了维度**：只按接口限流，不按用户/IP，结果一个用户就能打满全局限额

## FAQ

**Q：滑动窗口的格子数取多少？**
10 个格子是常见选择（精度约 10%）。格子越多越精确，但内存和计算量也越大。

**Q：固定窗口的突刺问题能彻底解决吗？**
不能，只能缓解。真要精确就用令牌桶或滑动日志。
