# CI 流水线配置

本文说明团队的 CI 流水线设计与配置，覆盖构建、测试、镜像、部署四个阶段。

## 流水线概览

```
push/PR
  ↓
① 代码检查（lint + 格式）
  ↓
② 单元测试（覆盖率 ≥ 80%）
  ↓
③ 构建镜像（多阶段构建）
  ↓
④ 集成测试（docker-compose 起依赖）
  ↓
⑤ 推送镜像（打 tag）
  ↓
⑥ 部署（dev 自动 / prod 手动审批）
```

## 各阶段配置

### ① 代码检查

```yaml
lint:
  stage: lint
  script:
    - ruff check .
    - ruff format --check .
    - mypy app/
  cache:
    key: lint-$CI_COMMIT_REF_SLUG
    paths: [.ruff_cache/]
```

**要求**：lint 失败直接阻断，不允许"先合并后修"。

### ② 单元测试

```yaml
test:
  stage: test
  script:
    - pytest --cov=app --cov-report=xml --cov-fail-under=80
  artifacts:
    reports:
      coverage_report:
        coverage_format: cobertura
        path: coverage.xml
  services:
    - name: redis:7-alpine
      alias: redis
```

**覆盖率门槛 80%**：低于阈值流水线失败。

### ③ 构建镜像

```dockerfile
# 多阶段构建：构建层 + 运行层
FROM python:3.12-slim AS builder
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

FROM python:3.12-slim
WORKDIR /app
COPY --from=builder /usr/local/lib/python3.12/site-packages /usr/local/lib/python3.12/site-packages
COPY app/ ./app/
USER 1000:1000
CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8000"]
```

**要点**：

- 多阶段构建，运行镜像不含编译工具（体积从 1.2GB 降到 180MB）
- **非 root 用户运行**
- 固定基础镜像版本（`python:3.12-slim` 而不是 `python:latest`）

### ④ 集成测试

```yaml
integration:
  stage: integration
  script:
    - docker compose -f docker-compose.test.yml up -d
    - pytest tests/integration/
  after_script:
    - docker compose -f docker-compose.test.yml down -v
```

### ⑤ 推送镜像

```yaml
push:
  stage: push
  script:
    - docker build -t $REGISTRY/order-service:$CI_COMMIT_SHORT_SHA .
    - docker push $REGISTRY/order-service:$CI_COMMIT_SHORT_SHA
  only:
    - main
    - tags
```

**tag 规范**：`{service}:{git-sha}` + `{service}:latest`，禁止只用 latest（无法回滚）。

### ⑥ 部署

```yaml
deploy-dev:
  stage: deploy
  script:
    - kubectl set image deployment/order-service order-service=$IMAGE
    - kubectl rollout status deployment/order-service --timeout=300s
  environment: dev
  when: manual   # prod 需要审批
```

## 缓存与加速

| 缓存对象 | 命中后耗时 |
|---|---|
| pip 依赖 | 从 90s 降到 8s |
| Docker 层 | 从 120s 降到 15s |
| 测试数据 | 从 30s 降到 3s |

**Docker 层缓存的关键**：把 `COPY requirements.txt` 放在 `COPY .` 之前，依赖不变时复用缓存。

## 常见坑

1. **CI 里跑了 e2e 测试**：耗时 30 分钟，应该放夜间任务
2. **镜像用 latest 部署**：出问题无法定位版本
3. **测试依赖外部服务**：CI 环境连不上测试 DB，应该用 service 容器或 testcontainers
4. **没设并发限制**：多个 PR 同时跑集成测试，端口冲突

## FAQ

**Q：CI 应该跑多快？**
PR 流水线控制在 10 分钟内，超过会影响开发节奏。慢的测试（e2e、压测）放夜间。

**Q：怎么保证 CI 和生产环境一致？**
用同一个 Dockerfile 构建，配置通过环境变量注入，不在镜像里写死。
