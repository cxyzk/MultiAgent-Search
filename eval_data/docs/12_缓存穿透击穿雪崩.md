# 缓存穿透、击穿、雪崩

三个名字很像，但成因和应对完全不同。混淆它们会导致"用错药"。

## 一张表分清

| 问题 | 成因 | 表现 | 对策 |
|---|---|---|---|
| **穿透** | 查**不存在**的数据 | 请求直达 DB，缓存永远不命中 | 布隆过滤器 / 空值缓存 |
| **击穿** | **热点 key 过期** | 瞬间大量请求打到一个 key，全部落 DB | 互斥锁 / 逻辑过期 |
| **雪崩** | **大量 key 同时过期** 或 **缓存服务挂** | DB 瞬间被压垮 | 过期时间加随机 / 多级缓存 / 熔断 |

## 缓存穿透

**场景**：用户请求 `id=-1` 或 `id=99999999`（不存在），缓存没有、DB 也没有，每次都查 DB。

**攻击场景**：恶意用户遍历不存在的 ID，每次都穿透到 DB。

### 方案 1：空值缓存

```python
def get_user(user_id):
    key = f"user:{user_id}"
    cached = redis.get(key)
    if cached is not None:
        return json.loads(cached) if cached != "NULL" else None

    user = db.query_user(user_id)
    if user is None:
        redis.setex(key, 60, "NULL")    # 缓存空值，60 秒
        return None
    redis.setex(key, 3600, json.dumps(user))
    return user
```

- **优点**：实现简单
- **缺点**：海量随机 ID 会占满缓存（每个都存 NULL）→ TTL 要短（60 秒）

### 方案 2：布隆过滤器

```python
from pybloom_live import BloomFilter

bf = BloomFilter(capacity=1_000_000, error_rate=0.001)

def get_user(user_id):
    if user_id not in bf:          # 一定不存在，直接返回
        return None
    return query_from_cache_or_db(user_id)
```

- **优点**：内存占用极小（100 万条约 1.4MB），拦截率 99.9%
- **缺点**：**有假阳性**（说不存在一定不存在，说存在可能不存在）；**不支持删除**（用户删除后要重建）

## 缓存击穿

**场景**：某个热点 key（如首页 banner）突然过期，1 万个并发请求同时发现缓存没了，全部去查 DB。

### 方案 1：互斥锁（只让一个请求回源）

```python
def get_hot_data(key):
    cached = redis.get(key)
    if cached:
        return json.loads(cached)

    lock_key = f"lock:{key}"
    if redis.set(lock_key, "1", nx=True, ex=10):     # 抢到锁
        try:
            data = db.query(key)
            redis.setex(key, 300, json.dumps(data))
            return data
        finally:
            redis.delete(lock_key)
    else:                                             # 没抢到，短暂等待后重试
        time.sleep(0.05)
        return get_hot_data(key)
```

- **优点**：保证只有一个请求打到 DB
- **缺点**：其他请求要等待（延迟增加）；锁的实现要防死锁

### 方案 2：逻辑过期（永不物理过期）

不设 TTL，把"过期时间"存在 value 里：

```python
def get_data(key):
    cached = redis.get(key)
    if not cached:
        return None
    data = json.loads(cached)
    if data["expire_at"] > time.time():
        return data["value"]

    # 逻辑过期：异步刷新，当前请求先返回旧值
    if redis.set(f"refresh:{key}", "1", nx=True, ex=60):
        threading.Thread(target=refresh_cache, args=(key,)).start()
    return data["value"]        # 返回旧数据，保证可用性
```

- **优点**：请求永不阻塞，可用性最高
- **缺点**：会短暂返回**旧数据**（最终一致）

## 缓存雪崩

**场景**：凌晨批量预热缓存，所有 key 都设 `expire=3600`，一小时后同时过期 → DB 瞬间被打穿。

### 方案 1：过期时间加随机

```python
import random

ttl = 3600 + random.randint(0, 600)     # 3600-4200 秒之间
redis.setex(key, ttl, value)
```

**最简单也最有效**，一行代码解决 80% 的雪崩问题。

### 方案 2：多级缓存

```
本地缓存（Caffeine，TTL 5s）→ Redis（TTL 1h）→ DB
```

本地缓存扛住绝大多数请求，Redis 挂了还有本地兜底。

### 方案 3：熔断降级

缓存服务不可用时，直接返回默认值/静态页面，不查 DB。

## 三者的关系

```
穿透：查不存在的 key       → 缓存"没东西"，每次都要问 DB
击穿：一个热点 key 没了    → 单点压力打 DB
雪崩：一批 key 同时没了    → 整体压力打 DB
```

**优先级**：雪崩最危险（影响面最大），击穿次之（热点最痛），穿透最常见（但影响小）。

## 常见坑

1. **空值缓存 TTL 太长**：攻击者用 100 万个随机 ID，缓存被 NULL 占满，正常数据被淘汰
2. **布隆过滤器没预热**：重启后过滤器为空，所有请求都判"不存在"
3. **互斥锁没设超时**：持锁进程崩溃，锁永不释放，热点数据永久不可用
4. **多级缓存不一致**：本地缓存 TTL 太长，Redis 更新后本地还是旧值

## FAQ

**Q：缓存预热怎么做？**
启动时批量加载热点数据，或者用定时任务在低峰期刷新。预热时**不要设统一的过期时间**。

**Q：布隆过滤器能删除元素吗？**
标准布隆过滤器不能。需要删除用**计数布隆过滤器**（Counting Bloom Filter）或**布谷鸟过滤器**（Cuckoo Filter，支持删除）。
